# ECC200 dimensions and partial-size selection

`^BX` columns (`c`), rows (`r`), and aspect ratio (`a`) constrain both the
ordinary byte encoder and the explicit FNC1/ECI/structured-append codeword path.
The encoder must not replace an unsatisfied constraint with a square symbol.
Legacy-quality dispatch and the renderer's empty-field suppression are unchanged.

## Fixed rows with automatic columns

With `c=0,r=12,a=2`, select the standard 26-column symbol before fitting data.
Do not widen automatically to 36 columns when the input is too long.
The renderer skips a capacity-rejected field in this row-only rectangular mode
and continues rendering the rest of the label. Direct encoder APIs return an
error. Invalid dimensions, conflicting shapes, and malformed escape sequences
still return errors. This is deliberately not a general implementation of
`^CV` diagnostics or of all printer field-rejection behavior.

The selection rule uses the smallest matching standard symbol for fixed rows
with automatic columns. Labelary also confirms this at `r=8` and `r=16`.
The operator also reported consistent physical results for the r8 and r16
controls below. Those reports establish symbol presence/absence, not decoded
module equality.
Both dimensions automatic continue to select a fitting symbol. DMRE sizes are
not enabled by this change.

## Independent evidence (2026-10-06)

Physical controls used a Zebra ZD421, 300 dpi, firmware V93.21.17Z, 50 x 25 mm
labels, darkness 15 and speed 2. Native fields used `^BX`, not rendered graphics.
The operator confirmed that `ABC` at `c0,r12,a2` and `c26,r12,a2` prints the same
matrix, while `ABCD12345678901234567890efgh` at `c0,r12,a2` prints no symbol.
The same long payload prints at explicit `c36,r12,a2` in the comparison strip.
These are visual/operator observations, not a claim of independently decoded
module equality for every photograph.

Separate Labelary API calls confirmed the following boundary. All commands
used `^BXN,4,200,c,12,6,,2` and differed only in `c` and the listed field data.

| Payload | Characters | ASCII data codewords | c0 | c26 | c36 |
| --- | ---: | ---: | --- | --- | --- |
| `ABCD1234567890123490efgh` | 24 | 16 | 26x12 | identical 26x12 | not tested |
| `ABCD12345678901234901efgh` | 25 | 17 | no symbol | no symbol | 36x12 |
| `ABCD12345678901234567890efgh` | 28 | 18 | no symbol | not tested | 36x12 |

This is a data-codeword limit, not a general 24-character limit. Numeric pairs
consume one ASCII codeword each. Standard 26x12 has 16 data codewords; standard
36x12 has 22. Both are classic ECC200 rectangular sizes, not DMRE extensions.
The tests establish observable size selection, not the printer's internal
implementation or a universal rule for all Zebra firmware.

Additional Labelary controls used `^BXN,3,200,c,r,6,_,2`:

| Rows | Payload | c0 | Small fixed width | Large fixed width |
| ---: | --- | --- | --- | --- |
| 8 | `aB!cD?eF` | no symbol | c18: no symbol | c32: 32x8 |
| 16 | `aB!cD?eF#gH%iJ&kLaB!cD?eF#gH%iJ&kL` | no symbol | c36: no symbol | c48: 48x16 |

Two native-only physical test labels were sent once at SD15/PR2. The operator
reported that the printer behaves like Labelary for these controls.

## Regression coverage and provenance

- `tests/unit_datamatrix.rs` covers fixed/partial/automatic dimensions, ratio
  conflicts, the exact capacity boundary, special codewords, magnification,
  field suppression without losing subsequent fields/labels, and error retention.
- `testdata/unit/datamatrix_dimensions.zpl` is a text-free fixture with a
  separately fetched Labelary PNG. It includes successful and suppressed fields,
  the exact boundary pair, explicit 36x12, FNC1, and a trailing graphic.
  Its golden tolerance is **0.0%**; references are not generated by Labelize.
- Reference endpoint: `https://api.labelary.com/v1/printers/8dpmm/labels/4.005x8.01/0/`.
